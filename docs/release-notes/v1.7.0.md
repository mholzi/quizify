## v1.7.0 — Host From the Dashboard, and a Round of Pictures

Two of the three additions here are about the person running the game rather than the people playing it. Hosting stops meaning "leave the dashboard and go to the admin page", and setting up an evening stops meaning "do it all again from scratch". The third is content: the first shipped pack that actually uses the image support Quizify has carried, unused, since 1.3.0.

Eight release candidates went into this one. Four of the defects below were found by *playing* the game on a real installation — not by re-reading the code, and not by the test suite, which stayed green the entire time.

### 🎛️ Host controls, on a dashboard card

`custom:quizify-host-card` puts start, advance and end on a Lovelace view ([#278](https://github.com/mholzi/quizify/issues/278)). One resource, two densities: `mode: compact` is a single button that follows the game phase, sized for one thumb; `mode: expanded` adds the player roster with connection dots, the join QR, round progress, and the reveal / end / reset row — for a tablet that does nothing else. Place the card twice with different modes and you get "status here, controls there" without a second resource.

The card speaks the admin WebSocket that already exists and maps phases to actions the way `admin.js` does, rather than inventing transitions of its own. It registers itself as a Lovelace resource when Lovelace runs in storage mode; in YAML mode it logs the line to add instead of failing setup.

One honest limitation: the card reuses the admin token the admin page stores in your browser. A dashboard opened on a device that has never visited `/quizify/admin` has no credential and cannot get one — so it shows a link to open Quizify once, rather than buttons that would quietly do nothing.

The TV card sketched in the same issue was **not** built. Its only real justification was casting, and `/quizify/dashboard` already serves that view.

### 💾 Presets, so setup happens once

Packs, difficulty, rounds, timer and lightning can be saved under a name and re-applied with one tap ([#433](https://github.com/mholzi/quizify/issues/433)). Most hosts cycle through the same two or three configurations; the four built-in mode cards stayed unchanged and the saved ones sit above them in a scrollable row.

Presets live on the server, not in the browser, so one saved on the living-room tablet is there on your phone. Up to 20, names up to 40 characters, read and written through the admin-token gate; a corrupt file degrades to "no presets" instead of blocking setup.

A preset deliberately does **not** store the TTS or House Plays Along settings. Those describe your devices, not the shape of an evening.

### 🖼️ A round of pictures

**Bilderrätsel** and **Picture Round** — 17 image questions in German and English, behind the same pictures ([#537](https://github.com/mholzi/quizify/issues/537)). Paintings and objects from The Met's open-access collection (CC0) and two NASA photographs (public domain). Image questions have been supported since 1.3.0 and no shipped pack had ever used one.

Every licence was verified on the individual object record rather than assumed from the collection — two candidates were dropped for failing that check. Four more were dropped after looking at them: at quiz size a planet is a bright dot, and one much-loved NASA item turned out to be a black video still. That is why the pack holds 17 questions and not the 20 the ticket sketched. Filling it up would have meant shipping pictures you cannot recognise, which in a picture round is the whole product.

Packs can now point `image_url` at pictures shipped inside the integration ([#536](https://github.com/mholzi/quizify/issues/536)) — paths under `/quizify/static/`, alongside absolute `http(s)` URLs — so a pack carries its own images instead of depending on a third party's server that may vanish. Traversal and every other form stay rejected.

The library now stands at **30 packs / 3,857 questions**.

### 🔍 What playing it found

**The picture round shipped invisible.** Every image question rendered as text only, on the television *and* on the phone ([#540](https://github.com/mholzi/quizify/issues/540)). The server had just learned to accept local image paths; the dashboard, the player and the lightning round each kept their own `^https?://`-only check and discarded exactly those paths. No request for a pack image ever reached the server. The rule now lives in one place and mirrors the server's sanitizer.

**A five-round game ended after two rounds.** On the picture pack at easy difficulty, the auto Lightning Round claimed the last five easy questions out of the main queue, leaving nothing for rounds three to five — and the game simply stopped, with nothing on screen explaining why ([#544](https://github.com/mholzi/quizify/issues/544)). The "With kids" preset (5 rounds, easy) hit the same wall. Lightning now leaves the main game the questions it still owes, and skips itself when nothing is spare; a missing bonus round beats a game that stops early. A fixed difficulty still never drifts onto another rung — filling the gap that way would hand a hard question to the kids preset.

**The end screen was throwing.** Deciding whether to show the host's "Start New Game" block read a variable that does not exist in that module, so the render aborted at that line and left *both* the host block and the "wait for the host" note hidden ([#546](https://github.com/mholzi/quizify/issues/546)). Everything above it had already drawn, which is why the screen looked healthy. It only bit when the host flag had to fall back — a host whose page reloaded, and every non-host player.

**Home Assistant was flagging a blocking directory scan** on the first player render after every start ([#542](https://github.com/mholzi/quizify/issues/542)). The player's language chips are derived from the shipped bundles, and that scan sat on the event loop. It is now primed in an executor at setup.

Two more were caught during the candidate stage: the compact host card had no way to end a game ([#278](https://github.com/mholzi/quizify/issues/278)), and a preset chip could stay highlighted while the mode cards showed something else ([#433](https://github.com/mholzi/quizify/issues/433)). Neither ever lost or mis-saved a setting.

### 🧪 Under the hood

The suite stands at **1,376 tests**. Worth saying plainly: it was green through every one of the four defects above. It had no browser, so nothing exercised the render path; no game loop, so nothing noticed the question supply running dry; no event loop, so nothing saw the blocking call. The new tests close those specific gaps — the shipped JavaScript is now executed under node against a DOM stub, and the question-supply arithmetic is asserted against the real pack.

### 🙏 Thank you

Every fix in this release came out of running the thing rather than reading it. If a game does something odd at your table — a screen that looks fine but is missing a button, a round that ends early, a picture that never appears — that report is worth more than another pass over the code.
